# Problem Definition Learning Project

## Why This Project Exists

Most beginners jump straight into coding. They start building features, writing functions, selecting frameworks, and connecting APIs before they have clearly understood the problem they are trying to solve.

As a result, they often build something that works technically but fails to address the actual need. The code may be correct, but the solution is wrong.

Problem definition is one of the most important skills in software engineering, product development, and AI systems design. Unfortunately, it is also one of the least practiced skills among beginners.

This project is designed to teach problem definition through experience.

## The Core Idea

The fastest way to understand the importance of problem definition is to experience what happens when it is skipped.

In this project, participants are intentionally encouraged to start with incomplete requirements, make assumptions, and build an initial solution. As the project progresses, additional context, hidden constraints, and real user needs are revealed.

Participants quickly discover that:

* A well-written solution can still solve the wrong problem.
* Assumptions are often more dangerous than technical mistakes.
* Understanding stakeholders is as important as understanding technology.
* Requirements gathering is an iterative process.
* Problem definition should happen before solution design.

The goal is not to avoid mistakes but to learn from them.

## Learning Objectives

By completing this project, participants will learn how to:

* Identify the actual problem behind a request.
* Distinguish symptoms from root causes.
* Ask effective clarifying questions.
* Validate assumptions before implementation.
* Translate vague requirements into measurable objectives.
* Define success criteria.
* Recognize stakeholder needs and constraints.
* Build solutions that align with business goals.

## What You Will Experience

Throughout the project, you will:

1. Receive an intentionally vague problem statement.
2. Create an initial solution based on your understanding.
3. Discover hidden requirements and constraints.
4. Re-evaluate assumptions.
5. Refine the problem definition.
6. Redesign the solution based on new insights.
7. Compare the final solution with the original implementation.

This mirrors what happens in real-world software projects, where requirements evolve and understanding deepens over time.

## Key Takeaway

The purpose of this project is not to build the perfect application.

The purpose is to develop the habit of asking:

**"What problem are we actually trying to solve?"**

Before writing code, choosing tools, or designing architecture.

Mastering this skill will improve your effectiveness as a developer, architect, product engineer, business analyst, and AI practitioner.

## Expected Outcome

After completing this project, participants will have a practical understanding of:

* Problem framing
* Requirements analysis
* Stakeholder thinking
* Root cause identification
* Solution validation
* Iterative design

Most importantly, they will understand that successful projects begin with a clearly defined problem—not with code.
